# UI 重构与 s-review 自查

## 意图

在既有代码审查工作台内重排信息层级：桌面保留 PR 导航、审查文档、辅助上下文三栏；突出 PR 标题与审查结论，减轻问题列表的容器噪声。颜色跟随宿主主题，窄屏保留 PR 切换能力。保留发布、合并、评论和审查的数据契约及前一轮缺陷修复。

## 改动

- 替换旧的 Codex 截图硬编码样式段，复用宿主主题令牌；正文、问题列表、弹层不再固定使用深色。
- 列表补充仓库与 PR 编号，选中态有轮廓，行不再被 flex 压缩而重叠。
- 审查结果按结论、计数、筛选、问题详情组织；问题之间用分隔线而非重复背景卡片。
- 评论标题最多展示两行；没有 GraphQL 线程 ID 时隐藏解决操作。
- 窄屏将 PR 列表放在顶部横向滚动，工具栏自动换行。
- 移除没有编辑行为的标题铅笔；避免解决按钮的键盘事件被外层线程捕获为定位操作。

## 后续审查修复

后续 s-review 复现出两处缓存修复遗漏：缓存中运行的 B 在切换时误删 A 的缓存，以及失效前发出的请求在返回后重写旧快照。现已让轮询显式绑定 PR，所有详情读取与评论后刷新共用版本校验；旧响应只能复用或重新读取当前版本，不能写回旧值。较早请求清理时也不能移除较新的在途请求。详情加载不再覆盖其间启动的新审查。

响应式布局统一依据工作台容器宽度，新增内部布局容器以支持桌面宿主的窄面板，移除冲突的视口隐藏规则。

本次主线程复核了上述触发条件和回归测试；不是独立审查。

- `node --check plugin/client.js`、`git diff --check` 通过。

## 没查到的部分

使用真实 client bundle 和本地 mock Host 验证，没有连接用户的 DSH 宿主，也没有对 GitHub 执行发布、评论、解决或合并操作。中等宽度继续沿用既有右侧详情栏隐藏策略。
